Витрина автозапчастей: поиск по артикулу, проценка по складам, корзина и заказы.
Работает поверх API поставщиков — «Автоконтинент» подключён первым, но
архитектура рассчитана на то, что поставщики приходят и уходят.

```
autocase/
├── backend/     FastAPI-шлюз: адаптеры поставщиков → один каталог
└── frontend/    Next.js 16 + Tailwind v4: витрина
```

## Запуск

```bash
make install     # venv + зависимости обеих частей
make dev         # шлюз на :8000, витрина на :3000
```

Без кредов всё работает на демо-данных, и интерфейс честно об этом говорит
(`демо-данные · ключи не заданы` в шапке, `live_suppliers: 0` в `/api/health`).

## Подключение боевого API

Скопируйте `backend/.env.example` в `backend/.env` и впишите логин с паролем:

```
AK_LOGIN=ваш_логин
AK_PASSWORD=ваш_пароль
```

Больше ничего менять не нужно — адаптер сам переключится с фикстур на живой
`api.autokontinent.ru` и начнёт отдавать реальные остатки.

## Добавить поставщика

1. Напишите адаптер — подкласс `SupplierAdapter` (`backend/app/suppliers/base.py`),
   переведите его ответы в канонические модели из `app/domain/models.py`.
2. Зарегистрируйте тип: `@register_supplier_type("имя")`.
3. Опишите объявленные возможности в `capabilities` — фронт по ним прячет
   элементы управления, которых у поставщика нет.
4. Добавьте запись в `SUPPLIERS_FILE` или переменную `SUPPLIERS`
   (см. `backend/suppliers.example.json`).

Ни сервисы, ни роуты, ни фронт при этом не меняются. Поиск и проценка сами
начнут опрашивать нового поставщика параллельно с остальными, а корзина —
раскладываться по поставщикам и уезжать в заказ отдельными частями.

Чтобы отключить поставщика, поставьте `"enabled": false`.

## Архитектура бэкенда

```
app/
├── domain/       канонические модели, составные ID, capabilities
├── suppliers/    контракт адаптера, реестр, реализация «Автоконтинента»
├── services/     фан-аут по поставщикам: каталог, корзина, заказы
├── api/          роуты и схемы HTTP
└── core/         ошибки, TTL-кэш, логирование
```

Решения, которые стоит знать, прежде чем менять код:

- **Составные ID.** Наружу уходит только `<поставщик>:<родной_id>`, потому что
  у разных поставщиков идентификаторы пересекаются. Сегменты
  percent-кодируются, так что разделитель не встретится внутри значения.
- **Один упавший поставщик не роняет выдачу.** `services/fanout.py` собирает,
  что успел, и возвращает список проблем — интерфейс показывает их баннером
  «выдача неполная».
- **Мутации не ретраятся.** Повтор `basket/add` — это вторая строка в заказе.
  Ретраи включены только для чтения.
- **Количество в корзине меняется удалением и повторным добавлением** — у API
  поставщика нет операции обновления. Порядок «сначала удалить» выбран
  сознательно: при сбое второго шага мы пытаемся вернуть строку, и худший
  исход — заметная пропажа позиции, а не незаметный дубль в заказе.
- **Оптимистичная блокировка.** Удаление требует актуальной `version`; при
  конфликте корзина перечитывается, и удаление повторяется один раз.
- **Признак транзита — эвристика** по названию склада: в ответе API явного
  флага нет. Сама фильтрация при этом настоящая, через параметр `show_odds`.

### API шлюза

| Метод                           | Назначение                                   |
| ------------------------------- | -------------------------------------------- |
| `GET /api/health`               | состояние шлюза и поставщиков                |
| `GET /api/suppliers`            | подключённые поставщики и их возможности     |
| `POST /api/vin/decode`          | распознавание автомобиля по VIN              |
| `GET /api/search?q=`            | карточки по артикулу у всех поставщиков      |
| `GET /api/offers?q=`            | сводная проценка по артикулу                 |
| `GET /api/parts/{id}/offers`    | наличие и цены по конкретной карточке        |
| `GET /api/basket`               | корзина, сгруппированная по поставщикам      |
| `POST /api/basket/lines`        | добавить предложение                         |
| `PATCH /api/basket/lines/{id}`  | изменить количество                          |
| `DELETE /api/basket/lines/{id}` | удалить строку                               |
| `POST /api/basket/clear`        | очистить корзину (всю или одного поставщика) |
| `POST /api/basket/submit`       | оформить заказ                               |
| `GET /api/orders`               | история заказов со статусами                 |

Интерактивная документация — `http://localhost:8000/api/docs`.

### Точное распознавание VIN

Без дополнительных ключей VIN проверяется через открытую базу NHTSA. Это
полезный резерв, но для европейских автомобилей она часто знает только марку,
год и завод. Для точной комплектации подключается Laximo.CAT:

```env
LAXIMO_LOGIN=ваш_логин
LAXIMO_PASSWORD=ваш_пароль
```

После заполнения ключей Laximo автоматически становится основным источником и
возвращает доступные OEM-поля: модификацию, двигатель, коробку, дату выпуска,
рынок и дополнительные атрибуты. Если сервис не ответит или не найдёт VIN,
шлюз попробует NHTSA и честно отметит результат как частичный.

Ошибки всегда приходят одним конвертом, включая ошибки валидации:

```json
{ "error": { "kind": "supplier_unavailable", "message": "…", "detail": null, "supplier": "ak" } }
```

## Фронтенд

Next.js 16 (App Router), Tailwind v4, TanStack Query. Браузер всегда обращается
к собственному `/api`, а Next проксирует его на шлюз (`next.config.ts`), поэтому
CORS не нужен, а адрес бэкенда не попадает в клиентский бандл.

Поиск и карточка товара рендерятся на сервере (нужны для индексации), корзина и
заказы — на клиенте, потому что это интерактивное состояние.

Дизайн: тёплая бумага, один сигнальный оранжевый, нулевые скругления,
моноширинные данные с табличными цифрами. Тема переключается в шапке и
запоминается; светлая и тёмная равноправны.
