# Инструкции для агентов

Репозиторий: витрина автозапчастей поверх API поставщиков.
`backend/` — FastAPI-шлюз, `frontend/` — Next.js 16. Обзор проекта в `README.md`.

## Команды

```bash
make install                                   # зависимости обеих частей
make dev                                       # шлюз :8000 + витрина :3000
make test                                      # pytest
make lint                                      # ruff + tsc + eslint
make build                                     # прод-сборка фронта

cd backend && .venv/bin/python -m pytest tests/test_api.py -q   # один файл
cd frontend && npx tsc --noEmit                                 # только типы
```

Перед коммитом прогоняйте `make lint` и `make test`. Правки фронта проверяйте
сборкой: типы страниц App Router ловятся только на `next build`.

## Что нельзя сломать

Эти решения приняты осознанно, у каждого есть цена ошибки:

- **Составные ID.** Наружу уходит только `<поставщик>:<родной_id>`
  (`app/domain/ids.py`). Родные идентификаторы разных поставщиков пересекаются;
  склеивать их строками на месте нельзя — используйте `encode`/`decode`.
- **Мутации не ретраятся.** В `AkHttpClient` повторы включены только для GET.
  Повторный `basket/add` — это вторая строка в заказе клиента.
- **Падение одного поставщика не роняет выдачу.** Любой новый фан-аут делайте
  через `services/fanout.py`: он возвращает частичный результат и список
  `SupplierIssue`, а интерфейс показывает их баннером.
- **401 наружу не отдаём.** Ошибка авторизации у поставщика — это наша
  конфигурация, а не проблема покупателя: маппится в 502.
- **Смена количества = удалить + добавить.** У API поставщика нет обновления.
  Порядок «сначала удалить» выбран сознательно (см. `services/basket.py`).
- **Конверт ошибок один на все ответы**, включая ошибки валидации FastAPI:
  `{"error": {"kind", "message", "detail", "supplier"}}`. У фронта ровно один
  парсер неудачного ответа.

## Добавление поставщика

Подкласс `SupplierAdapter` + `@register_supplier_type("имя")` + запись в
конфиге. Сервисы, роуты и фронт при этом не меняются — если пришлось менять,
значит абстракция протекла, и чинить надо её, а не звать поставщика по имени.
Возможности объявляйте в `capabilities`: фронт по ним прячет неподдерживаемые
элементы управления.

## Стиль

**Python.** Строка до 100 символов, ruff (`E,F,I,UP,B`), полные аннотации типов.
Docstring — зачем модуль существует, а не пересказ кода. Комментарии на русском
и только там, где решение неочевидно.

**TypeScript.** Никаких `any`. Типы ответов шлюза живут в `src/lib/types.ts` и
зеркалят `app/domain/models.py` — меняете модель, меняйте оба.

**React.** Не копируйте внешнее состояние в `useState` через эффект: для DOM и
localStorage есть `useSyncExternalStore` (`lib/command-bus.ts`) и CSS-варианты
(`components/theme-toggle.tsx`). ESLint это проверяет.

Серверные компоненты — для поиска и карточки товара (нужна индексация),
клиентские — для корзины и заказов. Данные корзины держит TanStack Query по
ключу `["basket"]`; мутации возвращают корзину целиком, её кладут в кэш через
`setQueryData`, без лишнего перезапроса.

**Дизайн.** Тёплая бумага, один сигнальный оранжевый, нулевые скругления,
моноширинные табличные цифры для всех данных. Цвета берутся только из токенов
`globals.css` — хардкод hex в компонентах ломает тёмную тему. Оранжевый значит
«действие или лучшее предложение», декоративным он не бывает.

## Тесты

Бэкенд покрыт на уровне маппинга, транспорта, сервисов и HTTP. Фейковый
поставщик — `tests/fakes.py`; он же служит проверкой того, что второй поставщик
подключается без правок сервисов. Новую логику фан-аута тестируйте минимум
двумя поставщиками, один из которых падает.

## Данные без кредов

Пустые `AK_LOGIN`/`AK_PASSWORD` включают демо-режим: `FixtureApi` отдаёт сырые
ответы в формате апстрима, поэтому маппинг работает по-настоящему. Интерфейс в
этом режиме честно пишет «демо-данные · ключи не заданы» — не убирайте
индикатор, он спасает от разговоров о «неправильных остатках».
